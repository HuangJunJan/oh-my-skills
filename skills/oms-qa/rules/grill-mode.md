# 盘问 / 严审模式

## 进入条件

任一满足即进入：

1. **显式要求**：盘问我、严审、挑战这个设计、stress-test、grill me、brainstorm-style questions。
2. **用户交还提问权**：让我来问、要我提问、反过来问他的相似表述（问我、你来问、有什么要问我的）。
3. **需求缺口致命**：目标/范围/约束/前置条件缺失或矛盾，无法从资料/历史上下文补齐，且默认假设会带来正确性/数据/权限/安全风险，或目标本身相互冲突。

## 进入后行为

- 从最关键的不确定性开始，一次只问一组相关问题。
- 每组问题必须给推荐答案、理由、代价和替代方案。
- 能从代码或资料确认的事实先查，不拿来问用户。
- 发现不可逆、高成本、合规、安全、数据迁移等风险时，主动升级为严审。
- 结束时给「已确认决策 + 待办 + 风险」摘要。

## 标准格式

```text
Q1. <问题>
推荐：<建议答案>
理由：<为什么>
代价：<放弃什么>
替代：<另一方案及代价>
```

检查：每次盘问结束后自问"这轮盘问暴露了哪些之前不知道的风险？"
