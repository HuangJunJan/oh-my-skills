# Database Migration 工作流

## Task Anchor（任务锚点）

**Goal:** 安全执行数据库 schema 变更，兼容历史数据，可回滚。

**Boundaries:**
- 不直接在数据库上手动操作，走迁移工具
- 不修改已有迁移文件，只新增
- 不删除字段不做兼容处理

**Done When:**
- 迁移可回滚
- 相关索引已评估
- 兼容窗口已确认
- dry-run 通过
- AAR 扫描完成

---

## Step 1 — 确认变更
- 新增/删除/修改字段或索引
- 读 `rules/data-layer.md`

## Step 2 — 评估影响
- 是否影响历史数据（需要数据迁移？）
- 是否影响老客户端（兼容窗口？）
- 是否影响索引/约束

## Step 3 — 写迁移
- 使用项目迁移工具
- 新增高频查询同步添加索引
- 删除字段同步处理索引/约束

## Step 4 — 验证
- dry-run 优先
- 本地库或测试库验证
- 说明回滚策略和兼容窗口

## Step 5 — 交付
- 走 `$oms-meta/workflows/task-closure.md` AAR

### Gotcha 检查
- [ ] 迁移可回滚
- [ ] 修改字段有兼容窗口
- [ ] 相关索引已评估
- [ ] SQL 使用参数化查询
