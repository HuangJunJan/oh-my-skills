# 修复策略

## 根因修复
修问题本身，不绕过症状。若过度 gate / mode / 兼容层导致问题，优先删除它们。
检验：修复后问自己"如果这段代码后来又被改了，同样的问题还会复现吗？"

## 复用优先
复用已有函数、hook、middleware、schema、类型、组件和项目惯例；不要基于猜测新建一套。
检验：新建的函数/类型/工具在项目中是否已有等价物？

## 删除自己产生的孤儿
本次改动造成的未引用代码、导入、变量、类型、配置同步清理。历史遗留死代码只提示，不顺手删。

## 拒绝 mode 堆砌
不要用 `bool` / `enum` / 字符串 `mode` / options bag 让一个函数承载多套本质不同的业务流程。
检验：这个函数的分支是"不同行为"还是"不同业务"？后者应该拆。

## 结构性问题结构性修
共享校验、权限、API 契约、数据迁移、状态同步、安全、跨模块重复 bug，要修公共边界。
