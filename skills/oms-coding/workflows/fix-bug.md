# Fix Bug 工作流

## Task Anchor（任务锚点）

**Goal:** 根因修复目标缺陷，最小改动，不引入副作用。

**Boundaries:**
- 只修用户请求的 bug，不顺手格式化/重构/升级依赖
- 不扩大修复范围到邻近问题，除非确认是同一根因
- 不添加未要求的功能、校验、日志（除非是定位根因的临时手段）

**Done When:**
- 复现测试通过
- 根因可追溯
- 修复 diff 每一行都能对应用户请求
- 回归验证无副作用
- AAR 扫描完成

---

## Step 1 — 确认预期行为
- 用户/需求描述的行为应该是什么
- 当前实际行为是什么
- 差异在哪里

## Step 2 — 复现问题
- 构造最小复现场景
- 确认是稳定复现还是间歇性的
- 间歇性 bug：分析竞态/时序/缓存/网络条件

## Step 3 — 定位根因
- 从触发点沿着数据流/调用链追溯到责任边界
- 写复现测试/样例
- 读 `rules/debugging.md` — 禁止静默兜底

## Step 4 — 最小修复
- 修根因，不修症状
- 读 `rules/fix-strategy.md` — 根因修复 + 复用优先 + 拒绝 mode 堆砌
- 只改必须改的；不顺手格式化、重命名、升级依赖

## Step 5 — 回归验证
- 跑复现测试
- 检查修复是否引入副作用
- 读 `rules/verification.md`

## Step 6 — 交付
- 读 `rules/code-quality.md` 的交付前自检
- 写交付报告（改动、理由、验证、风险）
- 走 `../oms-meta/workflows/task-closure.md` AAR

### 完成前 Gotcha 检查
- [ ] 没有空 catch / except: pass / 吞错误
- [ ] 没有为"看起来能跑"加的 fallback/默认值
- [ ] 没有用 mode 堆砌绕过根因
- [ ] 没有顺手格式化/重命名/升级依赖
- [ ] 本次产生的孤儿代码已清理
- [ ] 每一行改动都能追溯到用户请求
