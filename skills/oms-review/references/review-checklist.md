# 完整审查清单 | Review Checklist

`$oms-review` 的系统性兜底清单,按审查顺序排列。**级别沿用 `rules/risk-levels.md` 的 Blocker / Major / Minor / Nit,不另立标准。** 这是检查项,不是硬指标——不要把它当成"必须全勾"的形式门槛,按变更类型取相关部分。安全/性能细项分别见 `security-review.md` / `performance-review.md`。

---

## 0. 审查前

- [ ] 拉取最新基线,读懂 PR/需求描述和关联 issue
- [ ] 判断变更类型:功能 / 修复 / 重构 / 安全补丁
- [ ] 圈定影响范围,留意是否夹带与目标无关的改动(scope creep)
- [ ] 能本地构建 / 跑测试时先跑;不能跑时记下、按 §5 说明

## 1. 需求与契约

- [ ] 是否满足需求和验收标准,有没有改无关行为
- [ ] 是否破坏既有契约:API 形状、数据结构、错误格式、状态码、权限、路由、样式、交互
- [ ] 改字段/参数/状态时,是否核对"上游输入 → 契约 → 下游消费"全链路
- [ ] 是否复用既有组件、工具函数、类型、schema、middleware、请求封装、测试模式

## 2. 安全(详见 `security-review.md`)

- [ ] 不可信输入未直接进 SQL / 命令 / 路径 / 模板 / 反序列化
- [ ] 受保护端点都有 authn;资源访问校验 authz(不止登录)
- [ ] 无硬编码密钥/凭证;敏感数据未在日志、错误、配置中泄露
- [ ] 口令用安全哈希;改状态接口有 CSRF 防护;CORS 按白名单

## 3. 代码质量

- [ ] 无静默兜底、吞错误、假成功、过度兼容、mode 堆砌、无意义防御
- [ ] 错误处理在合适层级:无裸 catch/`except: pass`,错误被 log/wrap/return/rethrow
- [ ] 命名语义完整;函数职责单一、嵌套浅、有 guard clause
- [ ] 无重复逻辑、无死代码、无被注释掉的旧代码
- [ ] 类型收敛复用,不在调用方重复定义;边界处理 null/空集合

> 复杂度、函数长度等只在明显影响维护时作为 Minor,不套用固定阈值。

## 4. 性能(详见 `performance-review.md`)

- [ ] 无可避免的 O(n²)+ 算法;数据结构选型合理
- [ ] 无 N+1;关键查询有索引、非 `SELECT *`;大结果集分页
- [ ] 资源(文件/连接/流)确保释放;连接池化
- [ ] I/O 并发、配超时;有缓存且失效策略正确

## 5. 测试

- [ ] 新增/改动行为有对应测试,断言有意义(非只跑通不校验)
- [ ] 测试相互独立、可重复,不依赖执行顺序、不用裸 sleep 等待
- [ ] 测试验证行为/契约,不绑死旧实现细节
- [ ] 覆盖错误路径、边界值、空/null 输入、并发场景、bug 回归用例

## 6. 兼容与迁移

- [ ] 破坏性变更有迁移路径、废弃告警、版本策略;调用方/客户端同步
- [ ] 数据迁移可回滚、有兼容窗口
- [ ] 改字段/状态/错误码不影响历史数据和老客户端

## 7. 依赖与供应链

- [ ] 新增依赖必要,无既有能力可替代
- [ ] 无已知漏洞、license 兼容
- [ ] lockfile、生成的 API client、schema 产物与源改动一致、可追溯

## 8. 文档与记录

- [ ] 公开 API、破坏性变更、配置变更同步文档 / changelog / 迁移指南
- [ ] 注释解释意图而非翻译代码;无过期注释
- [ ] TODO/FIXME 有关联 ticket;无残留死代码

## 9. 交付卫生

- [ ] 无调试代码、临时文件、真实凭证
- [ ] 无无关格式化、行尾、权限位噪音
- [ ] 未混入用户既有的、与本次无关的改动

---

## 定级映射

| 本清单命中 | `rules/risk-levels.md` 级别 |
|---|---|
| 数据损坏 / 安全漏洞 / 线上不可用 / 破坏公开契约 | **Blocker** |
| 明显 bug / 竞态 / 越权 / 错误处理缺失 / 测试会失败 | **Major** |
| 可维护性 / 边界体验 / 局部重复 / 覆盖不足 | **Minor** |
| 纯风格 / 微小一致性 | **Nit** |

## 使用提示

- 自动工具(linter / formatter / scanner)先跑,机械问题不靠人工挑。
- 把人工精力放在安全、业务逻辑、公开契约上,不在风格上 bikeshed。
- 每条问题给"级别 + 位置 + 影响 + 最小修法",不止指出问题。
- 没有实质问题就明确说"未发现需要阻塞的缺陷",不为凑数硬挑 nit(见 SKILL.md Red Flags)。
